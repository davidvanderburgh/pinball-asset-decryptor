### Playing clips the page's engine can't

The Tk panes decoded frames with ffmpeg and played sound with ffplay, so any clip ffmpeg reads played.  A `<video>` element plays only what its engine ships, so the page checks each clip (`canPlayType` on the clip's container + codec + pixel format, sent by Python) and, when the engine can't take it (ProRes, MPEG-4 Part 2, 10-bit, `.cdmd`, and every H.264 clip on Linux, whose Qt WebEngine has no H.264) or the element errors, asks `video.make_proxy`: `video_helpers.browser_proxy` makes an H.264 MP4 (or VP8 WebM where there is no H.264) preview copy with the same ffmpeg, from the backend's own frame stream + sibling audio for `.cdmd`, cached in `%TEMP%/pad-video-preview` by path + size + mtime and pruned after 7 unused days.  Checked in Edge: an H.264 pick plays directly, a ProRes `.mov` pick plays through its proxy.

## Owed

- **Tk's own saved widths are not carried over**: `column_widths["video"]` (this PC's: #0 431, len 143, res 168, fmt 180, aud 70, rep 224, conv 66) was dragged in a Tk window with no rail; it adds up to 1282 px, past a 1210 px window, and the web table at that window size is about 950 px wide.  Used as pinned pixels it would push the table into a sideways scroll with Convert off screen, so the web table fits its content instead and keeps its own drags under `video_web` (the Tk key is left for the Tk app).
- **The Check card… window lives on the Video tab**: switching tabs hides it (a running check carries on) and it is back, with its report, on return.  Tk's Toplevel stayed over every tab; that needs the shell to host tab-owned windows the way it hosts Fonts and Scenes.
- **`.cdmd` preview proxy** (Big Lebowski): written against `core.video.open_raw_stream` / `audio_source_for` but not run on a real `.cdmd` (no TBL extract on this PC).
- **Linux / macOS engines on the real builds**: checked here with Playwright's WebKit (plays H.264 directly, no proxy) and with Edge told it has no H.264 (Qt WebEngine's answer: the VP8 WebM proxy is made and plays).  The `webui-builds` workflow's captures on the real Linux and macOS apps are still the final check.
- **Real-project screenshots**: the only project on this PC with clips is `gzho` (7 mode clips), and a scan there rewrites its `.hashcache.json`, so the captures use a generated Stern-like scratch project instead.  "Check card…" was run read-only against the real `godzilla_le-1_16_0` image.
- **"Tips - Video"** help window: shell (header ?) concern, not this tab.
- **Tk `_step_aside_for_jump`** in `reveal_video_slot` (it closes whatever the Scenes window needs out of the way): not needed while the Scenes window is a page dialog; revisit if it becomes a separate window.

## Core requests

1. (Done: `Table resizable widths onResize`.)  Left: the live drag measures on-screen pixels (`getBoundingClientRect`, `clientX`) and lays them out as page pixels, so at a zoom other than 100 % the column jumps while it is dragged (by the zoom factor); the tab divides the saved width by the zoom, so what is saved and shown after the drag is right.  `onResize` also hands every column's width, not only the dragged one: the tab measures the header at mousedown to tell which one changed.  Dividing by `document.documentElement.style.zoom` in `startResize`, and passing the dragged key, would fix both.
