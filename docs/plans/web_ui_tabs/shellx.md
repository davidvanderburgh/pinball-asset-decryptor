## Differences by design

- Theme is Dark / Light / Match the system (the frame's, in an Appearance cascade) and is not locked mid-run (Tk locked its synchronous re-style; a CSS theme is instant). Zoom is web-only.
- The ? opens a floating Tips panel beside the page (Tk: a separate window).
- Projects and Relink are floating panels inside the app window (Tk: separate OS windows); they sit under modal windows and the Tips panel.
- Change history opens in a window with the file's text and an "Open in text viewer" button (Tk opened the OS viewer directly).
- Form checks in New project / Save as show under the form (same words) instead of an error box; the window stays open.
- The first-launch disclaimer has no ✕ of its own: closing the app's window is the Quit (Tk: X = Quit).

## Core requests

1. Done: `tip()` no longer returns an `aria-label` (icon-only `Button`s have names).
2. Done: `window.select_tab` fans `on_tab_changed(ns)` to every service (`WebWindow.fans_tab_changes`); `ShellExtras._hook_tab_changes` is deleted.
3. Done: `compat.install` points `tkinter.messagebox` at the page for the whole web process; `shellx.install_prereqs` just calls the run logic.
4. The Tk-only modules still hold data the web UI shows: `gui/help_dialog.py` (HELP_CONTENT, GENERAL_CONTENT, sections_for), `gui/disclaimer.py` (the text), `gui/preview_dialog.py` (INTRO), `gui/picker.py` (`_MFR_VISUALS`, `_peek_text`), `gui/disk_dialog.py` (`scan_emu_cache`, `drop_emu_cache`), `gui/main_window.py` (VOICE_QUALITY_CHOICES, UPDATE_INTERVAL_CHOICES, normalize_update_interval; app.py imports these too), `gui/theme.py` (`detect_system_theme`). Move them to non-Tk modules before the cut-over deletes `gui/` (shellx imports them lazily with fallbacks; the choices are mirrored and a test keeps them equal).
5. Done: `openMenu` has one-level submenus; the gear and Project menus use them for Tk's cascades.
6. `window._mfr_card` reads `picker_tagline` / `picker_badge`, which no plugin has; the picker uses `shellx.picker` (the Tk fields: `badge`, `beta`, `unsupported_reason`, `input_spec.extensions`).
7. `openMenu` submenu placement: it opens at the row's right edge clamped to `innerWidth - 240` and never flips, so a right-aligned menu's cascade covers its own parent (and clips when wider than 240 px). Measure it after layout, open it LEFT of the parent menu when the right has no room, clamp its top to the window. `shell.js` `openShellMenu` / `fitSubmenu` does this for the frame's menus meanwhile (a MutationObserver on the menu host); once core does it, those become no-ops and can go.
8. `openMenu` keyboard: no Up / Down between rows, and Right opens a cascade without moving focus into it (no Left back). `shell.js` `menuKeys` adds them for the frame's menus meanwhile.
9. `Modal` Escape: every open `Modal` hears the key (document listener, no stack), and `MessageModal` / `PromptModal` do not stop it, so one Escape closes a whole stack (Projects → Properties, a confirm and its window, a prompt and its window). A module-level stack of open modals (act only when on top and `state.modals.open` is empty), with the question modals listening in the capture phase and stopping the event. `shellx_dialogs.js` `useWin` guards the shellx windows meanwhile (it ignores an Escape while its scrim is not the top one).
10. `openMenu` and zoom: it mixes window px (`getBoundingClientRect`, `innerWidth`) with style px, so at 125 % the gear menu opens off the window (Edge and WebKit both: rects are zoomed, `offsetWidth` and `style.left` are not). Divide the computed left/top by the zoom (rect width / offsetWidth). `openShellMenu` / `placeMenu` re-places the frame's menus meanwhile; every tab's `openMenu` is still affected.
11. `window.py` defines `open_link` twice: the plain method at the end shadows the `@rpc` one, so `ui.open_link` is not a call. The log's link lines now call `shellx.open_link` (the Tk behaviour, with the "Couldn't open your browser" fallback); delete the duplicate so `ui.open_link` either works or goes.
12. `Button` drops `autoFocus` (it is not one of its props), so `MessageModal`'s default button is never focused and Enter does nothing on a message box (Tk: Enter = the default button). Pass `autoFocus` through (focus in an effect), or give `MessageModal` an Enter handler.
13. `webui/app.py` (`saved_theme or "dark"`) and `window.py` (`initial_theme or "dark"`) default to dark; the service corrects it after start-up (`_first_run_theme`). Taking the detected theme there would avoid the one render in dark.
