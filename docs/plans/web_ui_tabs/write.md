# Write tab (ns `write`): port status

Files: `pinball_decryptor/webui/tabs/write.py` (the service), `webui/write_scan.py` (the Modified Files scan and staged rows, Tk-free), `webui/write_dialogs.py` (Build / flash, Card diagnostics, Image Info as page dialogs), `webui/static/js/tabs/write.js` + `write_dialogs.js`, `webui/static/css/tabs/write.css`, `tests/test_webui_write.py`.

Source of truth: `gui/main_window.py` `_build_write_tab` (3219-3684) and the methods behind it, `gui/flash_dialog.py`, `gui/diagnose_dialog.py`, app.py `_start_write` / `_on_build_flash_request` / `_start_flash_image` / `_start_revert_all` (unchanged, inherited).

## Ported (by Tk section)

- **Destination toggle** (`caps.direct_ssd`: Stern Spike 2, JJP, DP): the plugin's `write_iso_label` / `write_ssd_label` with the Tk tooltips (medium-aware). Flipping it is `_on_input_source_change("write")`: rows swap, drives enumerate, the scan re-runs ("write destination changed"), the phase ladder is refreshed through the Extract tab's `_refresh_extract_phases`. Forced to image mode for every other plugin.
- **Original row**: read-only mirror of the Extract input (`write_upd_var`, Tk batch 19 one-way mirror, hooked in this service), label `Original <noun>` / `Original .ext` / `Original`, tooltip, and the ⓘ (Tk's tooltip "Technical details about this image", kept on the line of the path's last characters however the path wraps) that opens **Image Info** (`core.image_info.collect` on a worker, Refresh, Copy Report, Close).
- **Detect badge** (image mode only, only while it has text): "Not recognised as …", "Looks like … — click to switch" (clickable, switches manufacturer and keeps the path), "Matches multiple manufacturers: …", "Extract only — this format has no Write/Replace support." Detection runs off the loop.
- **Project Folder**: link that opens the folder (`core.desktop.open_path`), the Tk "(no project yet — extract into one on the Extract tab)" note when empty, the "Open folder" messages. Mirrors the Extract output exactly as Tk did (empty included).
- **.checksums.md5 warning** (both wordings, with the ancestor suggestion), re-evaluated on tab entry, drawn directly under the Project Folder value as Tk packed it (`after=self._write_assets_row_ref`), so it is on screen with the row it is about.
- **Game SSD row** (direct mode): drive list from `core.drives` on a worker, auto-pick + the same log lines ("Selected SSD: …", reason, "If this isn't the …", "(hid N drive(s) …)"), Refresh, `write_drive_var` = the device path.
- **Direct-mode notes**, directly under the Game SSD row as Tk packed them: red safety banner (plugin text), the Windows "Administrator privileges required" panel with the primary button disabled when not elevated (note: "… — see the warning above."), the elevated UNC hint, the macOS Full Disk Access panel with "Hide this notice ✕" (persisted through `on_fda_acknowledge`, and handed to every tab showing the panel through `window.acknowledge_macos_fda`). The Administrator panel's collapsed flag is ONE flag with the Extract tab's, as Tk's `_admin_warning_collapsed` drove every admin frame: the Extract tab holds and persists it (`on_admin_warning_collapsed_change`); Write's toggle flips it there (`_toggle_admin_warning`) and Write re-reads it on entry. `set_admin_warning_collapsed(v)` is defined for a window-level fan-out.
- **BOF**: the editable-assets tip (grey italic, under Project Folder, as Tk packed it before the Build Image row), the **Update version** row (Auto + date + hint), `write_version_override()` / `write_version_validation_error()` with the Tk messages.

- **Advanced text grow** (replace_text + write = Stern): label, tooltip, `write_text_grow_var`, `on_text_grow_change` (persists + `PAD_STERN_TEXT_GROW`), re-lists the pending text rows in place.

## Layout

The design (`pages/Write.html`): page head with the change-count chip, Export CSV and Revert all; left column Destination card (toggle in its header, the rows with Tk's coloured lines under the row each belongs to: the .checksums warning and BOF's tip under Project Folder, the safety / admin / FDA / UNC notes under Game SSD; the primary button in its footer), the "Before you build" card (pre-build problems, hidden when there are none), Apply Delta and How to Install; right column Modified Files (legend in the header, Refresh, a virtual table with draggable File / Type column edges that scrolls inside the card, the total in the footer). The two columns stack when the tab itself is narrower than 980 px (a container query, so the global zoom stacks them too); the file list never sizes the page.

## Owed / deliberate differences

- The Linux and macOS app builds were not run from here (the `webui-builds` workflow is the lead's); the WebKit capture is the closest check made.

- **Direct write on Stern / JJP has no button, as in Tk.** Tk hides the plain Build/Apply button on flash_image plugins, and in "Write to SD card" mode the Build / flash dialog cannot build (no build location), so a direct SD write cannot be started from Stern or JJP in Tk either. Kept as is (parity); David should decide whether "Write to SD card" should show the `write_direct_button` there. DP (direct, no flash) has its "Apply Modifications" button.
- The Tk "?" tips window for Write is the shell's (Help menu), not this tab's.
- `gui/disk_dialog.py` (WSL disk space) is opened from the ⚙ menu, not from Write: not part of this tab.
- The page note under the Build / flash button ("One dialog: build an image, write it onto the …, or both. It reads Cancel while it runs.") is the design's wording.

## Core requests

1. DONE (framework): `window.acknowledge_macos_fda` fans out; Write's "Hide this notice" now calls it.
2. DONE (framework): the status bar no longer shows a second Cancel on the tab that owns the run.
3. Image Info is one window in Tk shared by Extract and Write; this tab has its own copy (`write_dialogs.ImageInfo`). A shell-level one would serve both.
4. **Open, ready for a two-line shell change.** The Build / flash dialog must show over ANY tab (Tk opened it over the Multi-boot tab without changing tabs). `js/tabs/write_dialogs.js` exports `WriteOverlays`: in `js/shell.js`, `import { WriteOverlays } from "./tabs/write_dialogs.js";` and render `<${WriteOverlays} />` beside `<${FontsWindow} />`. On mount it loads write.css if missing and calls `write.flash_host_ready`; from then on the Write page stops drawing its own copy (`flash_hosted`) and `WriteTab._open_flash_dialog` no longer switches tabs (`tests/test_webui_write.py::test_hosted_flash_dialog_stays_on_the_calling_tab`). Until then the fallback switch stays, without the Write tab's MD5 rescan; the phase row swap and Multi-boot's `on_show` on return are the window's and remain.
5. `text_grow_enabled` is exported by the Text tab too (it delegates to `write_text_grow_var`, so the answers agree).
6. `Modal` has no way to keep Escape / ✕ but ignore a backdrop click. Tk's Build / flash and Card diagnostics windows were grabbed; `write_dialogs.js` wraps them in a `display: contents` host that stops the backdrop's mousedown in the capture phase (`keepOnBackdrop`). A core `scrimClose={false}` option would replace it.
7. The Administrator panel flag has no window-level owner: Write flips the Extract tab's (`_toggle_admin_warning`) and re-reads it on entry. A window `set_admin_warning_collapsed(v)` that stores and fans out (Write defines the hook) would make it symmetric without Write reading Extract's attributes.
