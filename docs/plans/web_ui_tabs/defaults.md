Files: `pinball_decryptor/webui/tabs/defaults.py`, `pinball_decryptor/webui/static/js/tabs/defaults.js`, `pinball_decryptor/webui/static/css/tabs/defaults.css`, `tests/test_webui_defaults.py`.

Tk source: `gui/main_window.py` `_build_settings_tab` and the `_settings_*` methods (12917-14633), the tab-change branch for "Default Settings" (17540-17552), `_modes_settings_staged` (15334-15366), the `reload_assets_tabs` overlay (8014-8023); run logic `app.py` 5504-5705.

Shown for: Stern Spike 2 and Spike 1 (`capabilities.settings_editor`); hidden for Whitestar and every other maker (the shell's gate).

## Ported (by Tk section)

- **Card Image row**: a read-only mirror of the Extract tab's input, synced on every visit (`on_show`) and on an era switch while the tab is selected; the firmware is read on a worker thread (`read_image`, the same plugin calls: `detect_spike1_game`, `Spike1Adjustments`, `CardImage.adjustment_table`, `menu_visibility.statuses` / `widen_plan`, `factory_volume.find`, `curated_rows`, `all_rows`, `HighScoreDefaults`). A load whose path changed while it ran reloads. States: empty, "Reading the image's firmware…" (spinner), the error text, "None of the settings with friendly units…" (also every Spike 1 card), loaded.
- **Preset row**: the picker (a field-look button + `openMenu`) lists only the saved names, sorted, with a tick on the selected one, like Tk's read-only combobox; picking one loads it in display units and stages it EVERY time, the selected one included (Tk's `<<ComboboxSelected>>` fired on every pick, so re-picking put the preset back over edits; a native `<select>` only reports a change of value). `pick_preset("")` is not a choice and changes nothing. Save As… (the "Load a card image first…" info box, then `compat.simpledialog.askstring("Save preset", 'Name this preset (e.g. "My route"):')` in one step, as Tk's `_ask_text`; cancel or blank saves nothing; stores INTERNAL values), Delete (askyesno "Delete preset "X"?"), "Apply this preset automatically to every card I build" (greyed until a saved preset is selected; the "Auto-apply" info box; persisted through `on_default_presets_change`, which the run logic's `_apply_active_preset_to_build` reads). All status messages as Tk.
- **Curated form**: one column, group headings, Setting / On card / New default / ● / Range with Tk's tooltips; toggle / "N - Label" dropdown (blank, and not pickable, when the shipped default is out of range) / number spinner (core `Field`: `min`/`max`/`step` from the adjustment, travel takes in an out-of-range default, width from its widest value); help tooltips plus the Service menu / Debug notes. The setting's name is the `<label>` of its box (not of a tick: clicking the name must not toggle it).
- **High Scores block**: Slot / Initials / Player name / On card / Default score / ● / Range; initials and names hard-capped at the slot's room (`Field maxLength`, disabled at 0; the service caps too) with Tk's tooltip; accessible names "<slot> initials" / "<slot> player name" / "<slot> default score"; champion scores with no name record as score-only lines; every score row is an ordinary settings row (staging, presets, Reset). In a narrow window (`html.bp-1020`, the effective width, so zoom counts) the rows drop their 830 px minimum and each Range goes onto a second line under its score, so the Range column (and Led Zeppelin 1.22's "card ships 2,000,000, outside its own range") never hides in a side scroll.
- **Typed numbers** read the way a Tk `IntVar` did (`_as_int`): a whole number, else a decimal truncated toward zero ("7.5" is 7, as `getint` then `int(getdouble())`), else nothing (a blank row, not staged; the editor's OK refused).
- **All settings on this image**: virtual table (Setting "CAPTION  (0xNN)" / On card / New default / Range / Menu), click-to-sort with Tk's cycle (value columns open descending, third click = firmware order), draggable column widths (`Table resizable`; kept for the session like a Treeview's, never saved, as Tk), "Only settings not in the Adjustments menu" filter, the legend (both wordings), double-click / Enter opens the "Default setting" editor (caption, AD name, "On card: X        range", the fresh-card line, the Debug / Service note, toggle / dropdown / spinner, Back to card value / Cancel / OK; OK clamps a changed value, a non-number is refused). The editor takes the keyboard as Tk's `focus_set` + `grab_set` + `dlg.bind("<Return>")` did: focus starts in the editor (a spinner's text selected, so typing replaces it), Return presses OK from the spinner, the dropdown and the tick alike, Tab stays in the dialog, the list behind takes no keys while it is open (an arrow + Return used to swap the open setting), and focus goes back to the list afterwards so the next arrow / Return carries on. An edit from the list joins the rows (extra row) exactly as Tk.
- **Show hidden settings in the machine's menu…**: enabled only with a widen plan; the dialog's paragraph, the amber code-edit caveat, the "Show through this setting | Id" list (Id narrow, as Tk's 60 px column; columns draggable) opening on the staged name or the last non-`_CHANGED` entry, the count line, Leave the menu alone / Cancel / Show them; staged BY NAME with Tk's log lines and status. Focus starts on its list (arrows move the pick), Tab stays inside, no Return binding (Tk had none).
- **Staging and the log**: every edit auto-stages (500 ms debounce) into `.staged_changes.json` (`settings` internal units, `high_scores`, `menu_expose_through`), the raw-vs-clamped change test, project history lines, `on_folder_state_written`, "Set the project folder on the Extract tab first — changes stage with the project.", "N change(s) staged — baked into the next card you Build." / "Nothing staged."; one log line per field on commit (blur / Enter) or after 1.4 s idle; first look at a card adopts silently.
- **Reset Fields**: fields and names back to the card, staged settings / high scores / menu widening cleared, Tk's status and log line.
- **Overlay on load**: auto-apply preset first, then the folder's staged values, extra rows for staged hidden settings, the status summary.
- **Run-logic exports**: `staged_default_settings`, `staged_high_scores`, `staged_menu_expose` (same types and semantics), plus `settings_image_var`, `settings_preset_var`, `settings_autoapply_var`, `_modes_settings_staged`.
- **Cross-tab**: `reload_assets_tabs` (mod-pack import / transfer) re-overlays the folder's staged values.

## Deliberate differences from Tk (bugs not carried over)

- The first log line for a field now reads "Master Volume 30 → 24 …"; Tk's `(was or now)[2]` printed the new value twice ("24 → 24").
- Staged high-score initials / names are put back into the entries when a card loads. Tk left the entries at the card's text, so the next unrelated edit silently removed them from the staged record.
- Delete is greyed while no saved preset is selected (Tk's button did nothing then).
- `reload_assets_tabs` overlays only once a card has been read (Tk's unconditional call enabled Reset Fields with no card).
- The Service menu / Debug note is also shown as a small tag beside the setting's name (Tk had it only in the tooltip).
- In the "Default setting" editor, Return on a focused footer button presses THAT button (the web convention); Tk's dialog-wide `<Return>` pressed OK even from "Back to card value" or Cancel. From the editor itself Return is OK, as Tk.
- A value the editor's OK refuses (no number at all) turns the box red; Tk's OK silently did nothing.
- The Preset picker is greyed while no preset is saved (Tk's combobox opened an empty list).

## Core requests

All three are done in the framework and used here; the local workarounds are gone:

1. Text prompt: `compat.simpledialog.askstring` (dialog kind "prompt") asks the preset name from Python in one step. `PresetModal`, the `{"ask": true}` reply and `save_preset(name)` were removed.
2. `Field` `maxLength` / `min` / `max` / `step` / `width`, with `onCommit` after the flushed `ui.set`: every spinner, initials and name box is a core `Field`. The local `Input`, `editVal` and `doneVal` were removed.
3. Row `user-select: none` for clickable rows is in app.css (`.tbl .tr.click`); this tab's own rule was removed.

Not requested (handled in this tab): a dialog that owns the keyboard (focus in, Tab kept inside, Return = default action, focus back after, the list behind ignoring keys) is `useDialogKeys` in defaults.js; core `Modal` could offer it to every tab.
