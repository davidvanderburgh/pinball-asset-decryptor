# Emulate tab (Stern Spike 2), web port: status

The port of `gui/emulate_tab.py:EmulatePanel` (6.5k lines) to the web UI.

Files: `pinball_decryptor/webui/tabs/emulate.py` (the service, ns `emulate`), `pinball_decryptor/webui/emulate_rig.py` (the one seam to the rig helpers), `pinball_decryptor/webui/static/js/tabs/emulate.js`, `pinball_decryptor/webui/static/css/tabs/emulate.css`, `tests/test_webui_emulate.py`.

Visible only when the manufacturer's capabilities say `emulate` (Stern, era SPIKE 2), as in Tk. The service exists for every manufacturer and its pollers run in the real app whatever is picked, exactly as the Tk panel did (it was built for every manufacturer), so a quit takes a running emulator down.

## How it is built

- The service mirrors the Tk panel method for method (`start`, `stop`, `_apply`, `_poll`, `_prepare_overrides`, `_slots_paint`...). What the panel did to a widget it does to the store; `after` is the UI loop's; worker → loop handoffs are `loop.post`.
- Every helper the panel called is CALLED, not copied: `webui/emulate_rig.py` re-exports the module-level functions of `gui/emulate_tab.py` (setup probe/notice/report, `state_text`, `watch_cmd`, `kill_cmd`, `load_cmd`, cache list parsing, override-set policy...) and the panel's word lists (countries, power choices, tooltips, the overrides hints) from `EmulatePanel`'s class attributes.
- Every process goes through `_run` / `_popen` (tests replace them). Every command is built on a worker, not the UI loop (see Core requests: `core.runtime.status` may run `wsl.exe -l` off the main thread).
- `PAD_UI_NO_RIG` (captures, tests): no setup probe, no Docker probe, no status poll, no pre-cache, no boot-menu probe, no audio control file seeding; commands are built with a pure builder that consults nothing, and `_run`/`_popen` refuse.

## Core requests

1. DONE in the framework (`webui/window.py` EMULATE_PHASES is now the Tk ladder). Was: `EMULATE_PHASES` read ("Copy card", "Boot", "Tech Alerts", "Attract"); the Tk ladder is ("Copy card", "Boot", "Node boards", "Ready") (MainWindow.EMULATE_PHASES; JJP "Restore image", "Boot", "Game", "Ready"; Spike 1 "Extract", "Boot", "Node boards", "Ready"). This tab sets its own on show with `set_emulate_phases`; the default and the per-tab choice belong in `_show_row_for_tab`.
2. DONE in the framework (`select_tab` hands the footer back). Was: leaving an emulate tab should hand the footer back ("Ready", bar 0), as Tk's `_on_tab_changed` did; today the status text of the emulator ("Game running") stays on the next tab.
3. `core/runtime.status()` only avoids spawning `wsl.exe -l -q` on the MAIN thread; the web UI loop is not the main thread, so any `rig_cmd`/`wsl_head` built on the loop can run WSL there (a freeze, and a WSL call in tests). This tab builds every command on a worker, and `launch_as_root()` is warmed on the setup probe's worker; other ports (Multi-boot, JJP, Spike 1) meet the same trap. Proposed: treat `ctx.loop.in_loop()` like the main thread there.
4. Before the Tk code is deleted: move the Tk-free helpers of `gui/emulate_tab.py` (module level) and `EmulatePanel`'s word lists into a Tk-free module (e.g. `core/spike2_rig.py`), and make `gui/_runtime_ui.py` take its dialogs as arguments. `webui/emulate_rig.py` is the only file that imports them; its imports then change. Also give `_runtime_ui` a text function for `offer_from_file`'s question (title, message, picker title) and let its install run on a thread the caller names: the web tab now calls `ask_before_replacing` itself, but keeps that one sentence as `emulate_rig.from_file_question`, because `offer_from_file` installs (a 370 MB import) and asks `runtime.status()` on the calling thread, which is the UI loop.
5. Global zoom is CSS `zoom` on `<html>`, which neither the viewport media queries (rail collapse at 1180, stacking at 1020) nor container queries see in Edge: at 150% on a 1440 px window this tab keeps two columns. It still fits and scrolls; proposed: set breakpoint classes from the effective width (`innerWidth / zoom`).
6. The Multi-boot port should call `window.service("emulate").play()` / `.run_card(path)` (the MainWindow seams).
7. `js/shell.js` StatusBar: while an emulate tab's footer shows a run (`footer.mode === "emulate"` and `footer.index >= 0`), the left chip should read `footer.status` (kind `ok` at `index >= phases.length`, `acc` below it) instead of "Ready" beside "Game running", as the design's status bar does; "Ready" only at index -1. The tab cannot reach it (review of 2026-09-22).
