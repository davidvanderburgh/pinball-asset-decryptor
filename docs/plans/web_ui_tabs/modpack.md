Files: `pinball_decryptor/webui/tabs/modpack.py`, `pinball_decryptor/webui/static/js/tabs/modpack.js`, `pinball_decryptor/webui/static/css/tabs/modpack.css`, `tests/test_webui_modpack.py`.

Tk source: `gui/main_window.py` `_build_modpack_tab` (3684-3997), `_browse_transfer_*` / `_prefill_transfer_dst` / `_transfer_refresh_meta` / `_transfer_probe_img_version` (21633-21790), `_open_folder_link` (21207), the Mod Pack part of `apply_manufacturer` (18133, 18158-18166) and of `_scan_assets_tab_by_name` (21818), reached from `invalidate_asset_scans` / `reload_assets_tabs` (7987-8012). ## Ported (by Tk section)

- **Tab gate**: `caps.modpack` (window `_gate`). Visible for stern (spike2, spike1), jjp, spooky, pb, cgc, dp, bof; hidden for ap, williams, data_east, sega, stern whitestar.
- **Project Folder row**: the shared `write_assets_var` shown as a link (tooltip "Shared by every tab — it is set on the Extract tab. Click to open it."). Click opens the folder in the file manager, or says "No project folder yet — set it on the Extract tab." / "This folder doesn't exist yet:" exactly as Tk's `_open_folder_link`. The service traces whichever var the window returns for `write_assets_var` (the Write tab's once it is ported, a stand-in before) and re-binds on show.
- **Mod Pack box**: "Share your changes as a zip, or apply someone else's." (page subtitle), Export Mod Pack… and Import Mod Pack… with their Tk tooltips, which are also shown as the tiles' text. They call `app._start_export` / `app._start_import`: "Missing Input", "No Baseline Checksums", the mismatch question, "Save Mod Pack As", "Select Mod Pack ZIP", the "Import Mod Pack" confirm with "Details — skipped files", "Nothing to Import", "Export Complete" / "Import Complete" / failures.
- **Move Your Mods to Another Card** (only `caps.mod_transfer`: Stern Spike 2):
  - Route 1 heading, flow diagram (This project's mods -> transfer -> Stock card image(s) you pick -> build -> Finished modded card(s), last box accent-outlined), "Port + build onto card image(s)…" with its tooltip -> `app._start_port_mods` ("No project folder", "No staged mods found", the multi-image picker, the output-folder picker, the "Port + build N card(s)?" confirm, then the run on the footer).
  - Route 2 heading, flow diagram (1 Old extract (your mods) -> 2 New stock extract -> Write tab -> Modded card), the four numbered fields with Browse… (exact Tk picker titles, initial folders and file types), label tooltips on fields 2-4, Browse tooltips on fields 3-4, the version chips with their tooltip, field 4 auto-filled from field 2's `.extract_source.json`, the card-probe upgrade of chip 4 (debounced 500 ms, cached by file identity, off the UI loop, lands only if the field is unchanged; the chip column is 176 px, which holds the longest label, the filename guess "version ~ 1.13.0 (Release)", as Tk's 22-character label did; a longer one ends in an ellipsis and the chip's tooltip starts with the whole value), the output-name preview, "Transfer mods → new version…" with its tooltip -> `app._start_transfer_mods` (all its warnings and the reconciliation dialogs), and the green next-step line the run logic writes to `transfer_next_var`.
  - Destination pre-fill from the project folder when empty, as Tk: on manufacturer apply (mod_transfer only), on tab show, on `invalidate_asset_scans()` while Mod Pack is the visible tab (Open project, closing or archiving it, the end of an extract) and on `reload_assets_tabs()` whenever the tab is shown for the manufacturer (a mod-pack import, a transfer), which is Tk's `_scan_assets_tab_by_name("Mod Pack")` reached from both.
- **Optional: Apply Delta on Top** lives on the Write tab, as in Tk (`_build_write_tab`, gated by `caps.apply_delta` in `apply_manufacturer`); `webui/tabs/write.py` carries it. The copy this page used to show for dp and pb was removed (2026-09-22).
- **Exports** (window attributes app.py reads): `transfer_src_var`, `transfer_dst_var`, `transfer_oldstock_var`, `transfer_newimg_var`, `transfer_next_var`; also the read-only hint vars the Tk window carried (`transfer_output_var`, `transfer_*_ver_var`) and `_prefill_transfer_dst`, `_transfer_refresh_meta`.
- Buttons stay enabled during a run, as in Tk (its `set_running` never disabled them).

## Owed

- Nothing functional known. Cosmetic differences from Tk: the field labels carry a number badge instead of the "1. " prefix; "Browse..." / "...Pack..." use the typographic ellipsis like the rest of the web UI; the flow diagrams are HTML boxes (they follow the theme with no redraw).
- The Tk tab's long prose lives in the "?" tips window (help_dialog "Mod Pack"); the shell's Tips menu owns that.

## Core requests

1. A window helper to reveal a path in the file manager (Tk `_reveal_in_file_manager`: select a file in Explorer/Finder, open the folder on Linux via `core.desktop.open_path`). This tab carries a folder-only copy in `ModPackTab._reveal_folder`; Images and Text carry their own copies too.
2. Modal message indentation (owed, `static/css/app.css`, framework owner): `.modal .msg { white-space: pre-line }` collapses leading spaces, so the port confirm "Port + build N card(s)?" loses the `    -> <output>` indent under each source image, and "Your mods in:" / "Everything lands in:" / the import confirm's "Extract mod pack into:" lose the indent before their paths (`app.py` 3494-3510, 2721; Tk's native messagebox kept them). The fix is `white-space: pre-wrap` on that rule (`overflow-wrap: anywhere` already keeps long paths inside the modal). Not fixable from this tab's files: the modal is the shell's.
3. Done: the zoom-aware breakpoint classes (`html.w-rail`, `html.w-stack`, `html.bp-N`) replaced `@media (max-width)`; this tab never used breakpoints (it wraps by flex bases). The Extract page exists, so `webui_shot.py` no longer reports its 404.
